# Хяналтын самбарын бизнес дүрэм — local шалгалт

Огноо: 2026-10-14. Суурь production commit: `32b3501d8b4789972d7e1ad75bf36ca002d97fe7`.

Энэ засвар зөвхөн local орчинд байна. Push/deployment/migration хийгээгүй. Захиалгын мэдээлэл болон гүйцэтгэлийн төлөв өөрчлөөгүй.

## Одоогийн бизнес дүрэм

| Дараалал | Карт | SQL нөхцөл |
| --- | --- | --- |
| 1 | Төхөөрөмж тавиагүй | programming_completed IS TRUE AND installation_completed IS NOT TRUE |
| 2 | Программ суулгаагүй | installation_completed IS TRUE AND programming_completed IS NOT TRUE |
| 3 | Аль нэг ажил дутуу | programming_completed IS NOT TRUE OR installation_completed IS NOT TRUE |
| 4 | Урьдчилгаа төлөөгүй | advance::bigint + final_paid::bigint = 0 |

Эхний гурван нөхцөл handover_completed-ээр шүүхгүй. Хүлээлгэн өгсөн ч ажил дутуу захиалга тоологдоно. Гурав дахь карт эхний хоёрын захиалгууд болон хоёулаа дутуу захиалгыг зориуд агуулна.

Бүх карт өмнөх үндсэн идэвхтэй дөрвөн статус, returned_to_preorder_at IS NULL болон салбарын сонголтыг мөрдөнө. Цуцлагдсан хоёр статус хасагдана. Хүлээлгэн өгсөн захиалгын Дууссан статус нь идэвхтэй статусын жагсаалтад хэвээр.

NULL boolean-ыг ажил хийгдээгүй гэж үзнэ (IS NOT TRUE). Мөнгөний баганууд бодит schema-д NOT NULL DEFAULT 0. Хуучин NULL мөнгөн утга байвал төлбөргүй гэж баталгаагүйгээр тооцохгүй; SQL-ийн нийлбэр NULL болох тул картанд орохгүй. bigint нь нэмэх үед integer overflow-оос хамгаална.

Дөрөв дэх карт хэсэгчилсэн болон бүрэн төлбөртэй захиалгыг хасна. total_price, үлдэгдэл, handover_completed, receipt болон advance_type-ыг төлсөн дүнгийн оронд ашиглахгүй. Үнэ 0 байсан ч нийт төлсөн дүн 0 бол энэ картанд орно. Төлбөр бичих процесс болон үлдэгдэл тооцох бусад логик өөрчлөгдөөгүй.

Карт болон картын жагсаалтын SQL нь app/dashboard-queues.ts-ийн нэг shared функцээс үүснэ. Салбарын нөхцөл мөн shared. Энгийн жагсаалтын 500 мөрийн хязгаар нь картын SQL жагсаалтад үйлчлэхгүй.

Картын өнгө blue, green, violet, amber дарааллаар, хэмжээ болон responsive CSS хэвээр. Гурав дахь API түлхүүр workPending, жагсаалтын түлхүүр work-pending.

## Бодит өгөгдлийн зөвхөн унших шалгалт

Supabase-ийн Gas order төсөл (`xcnhqcctednqbneseibb`) дээр BEGIN READ ONLY, SELECT, ROLLBACK ашигласан.

| Карт | Хүлээгдэж буй | Бодит бүх салбар | Үр дүн |
| --- | ---: | ---: | --- |
| Төхөөрөмж тавиагүй | 10 | 10 | Таарсан |
| Программ суулгаагүй | 6 | 6 | Таарсан |
| Аль нэг ажил дутуу | 35 | 35 | Таарсан |
| Урьдчилгаа төлөөгүй | 8 | 8 | Таарсан |

Ажил дутуу 35 = зөвхөн төхөөрөмж дутуу 10 + зөвхөн программ дутуу 6 + хоёулаа дутуу 19. Урьдчилгаагүй боловч хэсэгчилсэн final_paid бүртгэлтэй 6 захиалга дөрөв дэх картанд орохгүй.

| Салбар | Төхөөрөмж | Программ | Аль нэг ажил | Төлсөн дүн 0 |
| --- | ---: | ---: | ---: | ---: |
| 16-ын салбар | 10 | 5 | 34 | 8 |
| Нарны замын салбар | 0 | 1 | 1 | 0 |
| 3-р салбар | 0 | 0 | 0 | 0 |

3-р салбарт хамрагдах идэвхтэй захиалга байгаагүй. Тоонууд нь шалгалтын үеийн snapshot; тоог хүчээр тааруулаагүй.
